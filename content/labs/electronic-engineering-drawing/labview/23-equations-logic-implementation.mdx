# Equations and Logic Implementation in LabVIEW

## Overview

Implementing mathematical equations and logical operations is fundamental to engineering programming. LabVIEW provides multiple methods for implementing equations, including graphical arithmetic functions and the Formula Node for text-based expressions. This laboratory session covers both approaches for engineering calculations.

## Objective

To implement arithmetic equations using LabVIEW's graphical math functions, use the Formula Node for complex text-based mathematical expressions, implement Boolean logic operations (AND, OR, NOT, XOR) for decision making, use comparison functions for conditional logic, and build a combined engineering calculator VI.

## Theory and Engineering Concepts

LabVIEW offers two approaches for implementing equations:
- **Graphical Functions**: Visual representation using Numeric palette functions (Add, Subtract, Multiply, Divide, Square Root, etc.)
- **Formula Node**: A structure that accepts C-style text equations, useful for complex expressions with multiple variables.

Boolean logic in LabVIEW uses functions from the Boolean palette (AND, OR, NOT, XOR, NAND, NOR, XNOR). These are essential for creating conditional program flow and decision-making logic.

## Project / Task

Create a VI that solves the quadratic equation ax² + bx + c = 0 and implements a component test decision system using Boolean logic.

## Procedure / Implementation

### Step 1: Implement Quadratic Formula (Graphical)

1. Create a new VI with controls for a, b, c
2. On the Block Diagram:
   - Calculate discriminant: `disc = b^2 - 4*a*c`
   - Calculate x1: `x1 = (-b + sqrt(disc)) / (2*a)`
   - Calculate x2: `x2 = (-b - sqrt(disc)) / (2*a)`
3. Wire all inputs to appropriate math functions

### Step 2: Implement Quadratic Formula (Formula Node)

1. Place **Formula Node** on the Block Diagram (Functions → Programming → Structures → Formula Node)
2. Add input terminals: right-click border → Add Input (a, b, c)
3. Add output terminals: right-click border → Add Output (x1, x2, discriminant, message)
4. Enter the formula:
   ```
   discriminant = b*b - 4*a*c;
   if (discriminant >= 0) {
       x1 = (-b + sqrt(discriminant)) / (2*a);
       x2 = (-b - sqrt(discriminant)) / (2*a);
       message = "Real roots";
   } else {
       x1 = -999;
       x2 = -999;
       message = "Complex roots";
   }
   ```

### Step 3: Boolean Logic for Component Testing

1. Create a component test logic VI:
   - Controls: Temperature_OK (Boolean), Voltage_OK (Boolean), Current_OK (Boolean)
   - Indicators: System_Pass (LED), Warning (LED), Shutdown (LED)
2. Implement logic:
   - System_Pass = Temperature_OK AND Voltage_OK AND Current_OK
   - Warning = (NOT Temperature_OK) OR (NOT Voltage_OK) OR (NOT Current_OK)
   - Shutdown = (NOT Temperature_OK) AND (NOT Voltage_OK)

### Step 4: Comparison Operations

1. Implement threshold detection:
   - Create numeric control for "Measured Value" and "Upper_Limit" and "Lower_Limit"
   - Use comparison functions:
     - `In_Range = (Measured >= Lower) AND (Measured <= Upper)`

## What Was Done

Created two implementations of the quadratic equation solver — one using graphical math functions and one using the Formula Node with C-style syntax. Both produced identical results for test inputs (a=1, b=-5, c=6 gave roots x1=3, x2=2). Built a component test decision system using Boolean logic with pass/warning/shutdown indicators. Implemented comparison-based threshold detection.
